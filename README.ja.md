# Sonic Assistant Bridge

PC のスピーカーとマイクで音響的な動きの候補を検知し、AI アシスタント向けに音声を含まないイベントを生成する実験アプリです。[KG-NINJA/SonicForceField](https://github.com/KG-NINJA/SonicForceField/tree/13fb3ba9c89a2bef36c364513dd4f2cc69709f0a) から派生しています。

[English README](README.md) · [導入・イベント形式](docs/assistant-bridge.md) · [公開状況と手順](docs/publication.md)

[リポジトリ](https://github.com/KG-NINJA/sonic-assistant-bridge) · [英語アプリ](https://kg-ninja.github.io/sonic-assistant-bridge/) · [日本語アプリ](https://kg-ninja.github.io/sonic-assistant-bridge/ja/)

明示的なマイク測定と、マイク・スピーカーを使わない合成デモに対応します。**dot は未接続です。** イベント送信は初期無効で、実装済みの送信先は明示的に有効化するローカル模擬受信だけです。

## ローカル起動

Node.js 22 以降と npm を用意し、ダウンロードしたソースディレクトリで依存関係を導入してください。

```sh
npm ci
npm start
```

`http://127.0.0.1:8765` を Chrome / Edge で開きます。開発用 UI は日本語、静的ビルドはルートが英語、`/ja/` が日本語です。Windows では依存関係の導入後、`start-sonic-forcefield.cmd` でも起動できます。ローカル実行にアカウントや API キーは不要です。

**デモを開始**を選ぶと、マイクの許可もスピーカー出力も使わず合成信号を解析します。イベントの `mode` は `synthetic` です。デモの成功は実機での検知成功を示しません。

## マイクを使う

1. HTTPS または localhost でアプリを開きます。PC の近くにあるスピーカーと実際のマイクを選びます。ヘッドホンやステレオミキサー／ループバック入力は適しません。
2. **マイクで測定を開始**（英語 UI は **Start microphone sensing**）を押します。ブラウザーのマイク使用許可に従って取得し、許可を求められたらこのページへの使用を許可します。ページを開いただけでは開始せず、停止後も自動再開しません。
3. PC を静止させ、送信音の受信確認と校正を待ちます。通常約 8 秒ですが、干渉があると延長したり開始できなかったりします。画面でマイク使用中・発音前・高周波音出力中を確認できます。
4. スピーカー付近で手を動かして変化を確認します。**停止**でマイクトラックを止め、発振器を消音・停止し、AudioContext を閉じます。タブの非表示やページ離脱でも停止します。通知されたマイクの中断・切断、音声処理の停止、測定中のクリップ、解析の遅延も停止条件です。

初期値は 20 kHz、デジタル出力振幅 2%、上限 3% です。振幅は実際の音圧でも安全性の保証でもありません。**音が聞こえる・不快な場合はすぐに停止してください。** 選択できる 18/19 kHz は聞こえる場合があります。感度設定で出力を自動増幅しません。

## イベントとローカル模擬受信

アシスタント向けイベント欄には `session.started`、`motion.detected`、`session.stopped` を表示します。日時、一時的な ID、モード、状態、理由、必要に応じて dB スコアだけを含み、生音声・録音・FFT 配列・会話本文を含みません。動きの重複を抑え、動きイベント同士に最低 3 秒の間隔を設けます。

ローカル受信を試す場合は、サーバー側でも明示的に有効にします。

```sh
BRIDGE_RECEIVER=1 npm start
```

PowerShell では `$env:BRIDGE_RECEIVER='1'` を設定してから `npm start` を実行します。画面の**イベントの送信先**で**この PC の模擬受信先**を選び、**模擬受信への送信を有効にする**を押してからデモまたはマイク測定を開始します。送信先は同じサーバーの `127.0.0.1` 上の `/bridge/events` に固定し、任意の外部 URL は指定できません。

**送信を無効にする**で配送を停止できます。タブの非表示や再読み込みでも送信設定は無効になります。通常の**停止**は測定を終了して終了イベントの送信を試みますが、次に明示的に開始する測定への送信設定は残ります。

```sh
npm run demo:bridge
```

このコマンドは一時的なループバック HTTP 受信サーバーを起動し、合成イベントの受信を確認して終了します。実機のマイク・スピーカーや dot は使いません。詳しい形式と受信制限は[ブリッジ導入文書](docs/assistant-bridge.md)を参照してください。

## 表示と検知の限界

| 状態 | 意味 |
| --- | --- |
| 接近・離反 | 音響的に、その方向の動きと整合する Doppler 成分を検知した候補です。 |
| 方向不明 | 支配的な方向を決められない動きの候補です。 |
| 遮蔽 | 受信した送信音が低下しています。物体、ミュート、音量変更などを区別できません。 |
| 動きなし | 現在は条件を満たす証拠がありません。不在や静止した人の在席を確定しません。 |

スコアは校正したスペクトル基準からの超過 dB、または遮蔽時の送信音の減衰 dB です。確率・信頼度・距離ではありません。波や矢印も実際の位置・範囲を表しません。「超敏感」の閾値は 1 dB、継続は 0.15 秒で、FFT 窓の時間幅も加わります。静止への復帰には 0.65 秒の落ち着いた状態が必要です。

機器の高周波特性、音声補正、環境音、扇風機、動く物などで誤検知や見逃しが起こります。静止した人、遅い動き、横方向の動きは見逃すことがあります。人物分類・距離計測・在席確認・防犯・緊急通知のための信頼性は検証していません。実機の検知範囲・成功率・精度は未確認です。

## データの扱い

マイクサンプルはブラウザーのメモリー内で処理し、録音・アップロードしません。分析サービスや外部の検知 API も使いません。状態や日時だけのイベントでも行動時間の手掛かりになるため、共有する前に内容を確認してください。プレビューと模擬受信の状態はメモリー上だけで、永続保存や配送保証はありません。静的 Pages ではバックエンドへのイベント送信はなく、サイトファイル取得とホストのアクセスログはマイク処理とは別です。

MCP Events アダプターは配送候補の形式を作る純粋な変換です。実際に dot へ接続するには、認証された MCP サーバー、購読、callback 検証、サーバー側署名と配送処理が必要です。この試作は接続や秘密を作成せず、ブラウザーへ認証情報を埋め込みません。

## 開発・検証

```sh
npm test
npm run lint
npm run typecheck
npm run check
npm run build
npm run build:pages
npm run test:browser
npm run test:microphone
```

最後の 2 コマンドは開発環境に Playwright と Chromium が必要です。既存インストールは `PLAYWRIGHT_MODULE` と `CHROMIUM_EXECUTABLE` で指定できます。本番の依存関係には含めません。`test:browser` はマイク取得・AudioContext 作成を禁止して合成 UI を確認します。`test:microphone` は Chromium の仮想マイクへ合成 WAV を入力し、発音をミュートしてブラウザーの media API、開始・異常系・後始末を確認します。物理マイク・実スピーカー・実環境の検知性能の試験ではありません。結果と画像は `artifacts/`、実行済みの範囲は[検証記録](docs/validation.md)を参照してください。

- `dist/`：Three.js を同梱したローカル実行用。Node.js 22 以降で、このディレクトリ内から `node server.js` を実行します。開発の検証コマンドはソース側で実行してください。
- `pages/`：静的な英語サイト、日本語は `pages/ja/`。Pages への配置対象はこのディレクトリだけです。
- `scripts/english.js`：静的ビルドの翻訳。英語のアプリソースに未翻訳の日本語が残るとビルドを失敗させます。
