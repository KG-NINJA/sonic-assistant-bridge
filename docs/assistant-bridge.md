# Sonic Assistant Bridge — 導入とイベント形式

SonicForceField の実験的な検知結果から、音声を含まない小さなイベントを生成します。初期状態はページ内プレビューだけです。マイク測定と合成デモに対応し、ローカル受信は明示的に有効化した場合のみ動きます。dot には未接続です。

この試作は [KG-NINJA/SonicForceField](https://github.com/KG-NINJA/SonicForceField/tree/13fb3ba9c89a2bef36c364513dd4f2cc69709f0a) のコミット `13fb3ba9c89a2bef36c364513dd4f2cc69709f0a` を基に、隔離した作業ディレクトリとブランチで開発しました。元のマイク・音出力の停止条件を維持しています。派生リポジトリは `KG-NINJA/sonic-assistant-bridge`、Pages 配信先は `https://kg-ninja.github.io/sonic-assistant-bridge/` です。元リポジトリや元の公開アプリへの反映は行っていません。

## 起動と音声を使わない試験

Node.js 22 以降と npm が必要です。

```sh
npm ci
npm start
```

`http://127.0.0.1:8765` を開きます。この通常起動ではイベントをページ内に表示するだけで、受信サーバーへの送信は有効になりません。**デモを開始**を選ぶと、マイクへのアクセスやスピーカー出力を行わずに合成信号で検知の流れを確認できます。**停止**、タブを隠す操作、ページ離脱によってセッションが終了します。

別途ローカル受信を試す場合は、サーバー起動時にも明示的に有効にします。

```sh
BRIDGE_RECEIVER=1 npm start
```

**04 / アシスタント向けイベント**パネルの**イベントの送信先**で**この PC の模擬受信先**を選び、**模擬受信への送信を有効にする**を押してから、**デモを開始**を選びます。成功すると**模擬受信を確認しました · dot 未接続**と表示します。ページ読み込みや有効化だけでは送信せず、その後のイベントを送ります。

配送先は同じサーバーのリテラル `127.0.0.1` 上にある `/bridge/events` だけです。任意の URL、外部サービス、dot の callback URL は入力できません。ブラウザーとサーバーの両方で有効化が必要です。**送信を無効にする**で配送を止められます。リロードやタブを隠す操作でも送信設定は無効になります。通常の**停止**はセンサーを止め、終了イベントの送信を試みますが、配送の有効設定自体は残ります。ページ離脱時などの終了イベントの到達は保証しません。

```sh
npm run demo:bridge
npm test
```

`demo:bridge` は合成イベント生成からローカル模擬受信までを確認するためのコマンドです。実マイク・音出力・実環境の検知精度・dot の応答を確認するものではありません。

開発時には `npm run lint`、`npm run typecheck`、`npm run check`、`npm run build`、`npm run build:pages` も実行します。Playwright と Chromium がある環境では、合成 UI の `npm run test:browser` と仮想マイクの `npm run test:microphone` を実行できます。既存のインストールを使う場合は `PLAYWRIGHT_MODULE` に Playwright のモジュール URL、`CHROMIUM_EXECUTABLE` に Chromium 実行ファイルの絶対パスを指定できます。前者はマイク取得と AudioContext 作成を禁止して合成デモだけを操作します。後者は Chromium の仮想デバイスへ合成 WAV を入力し、スピーカー出力をミュートして media API・開始・異常系・資源解放を確認します。どちらも物理マイクや実スピーカーの精度を試験しません。`artifacts/` に画像と JSON 結果を保存し、実行済みの範囲は[検証記録](validation.md)に記載します。Playwright は本番アプリの依存関係には追加していません。

ビルド済み `dist/` を使う場合は、パッケージ導入なしで `node server.js` を実行できます。模擬受信を有効にする場合は `BRIDGE_RECEIVER=1 node server.js` です。`npm test` や `demo:bridge` はソース側で実行してください。PowerShell では環境変数を `$env:BRIDGE_RECEIVER='1'` と設定してから起動します。

## マイク測定の開始と終了

Chrome / Edge で HTTPS または localhost のページを開き、実際の入力マイクと PC 付近のスピーカーを用意します。**マイクで測定を開始**（英語 UI は **Start microphone sensing**）を押したときだけ、ブラウザーの許可に基づいて入力を取得します。初回などは使用許可が表示されます。ページの読み込みだけで取得したり、停止後に自動再開したりしません。

受信確認と校正の間は PC を静止させ、画面のマイク・発音の状態表示を確認してください。通常は約 8 秒ですが、干渉で延びたり開始できなかったりします。初期の発音は 20 kHz・デジタル振幅 2%、上限 3% です。実際の音圧や安全性の保証値ではありません。聞こえる、不快などの場合は直ちに**停止**してください。18/19 kHz は聞こえる場合があります。

**停止**は入力トラックを終了し、発振器を消音・停止して AudioContext を閉じます。タブの非表示（`visibilitychange`）やページ離脱（`pagehide`）でも停止し、戻っても自動再開しません。許可待ちで停止した場合は、遅れて届いた入力も破棄します。マイクの中断・切断、音声処理停止、測定中のクリップ、解析の遅延も停止条件です。実機で期待どおりに検知できるかは使用するスピーカー・マイク・環境ごとに未検証です。

## イベントの意味

共通形式は `schemaVersion: 1` です。`id` はイベント UUID、`sessionId` はセッション UUID、`sequence` はセッション内の正の連番、`occurredAt` は UTC の ISO 日時です。`source` は `sonic-forcefield`、`mode` は `live` または `synthetic` です。

| `type` | 意味 |
| --- | --- |
| `session.started` | ユーザーが開始したセッション。状態は `STARTING`。検知可能・在席確認の宣言ではありません。 |
| `motion.detected` | センサーが検知した動きの候補。状態は `APPROACH`、`RECEDE`、`MOTION` のいずれか。 |
| `session.stopped` | 明示停止や安全停止によりセッションが終わったこと。状態は `STOPPED`。 |

`reason` は開始（`started`）、Doppler（`doppler`）、遮蔽候補（`occlusion`）、停止理由（`manual`、`page_hidden`、`pagehide`、`sensor_error`、`device_change`、`restart`）です。任意の会話文や音声を入れるフィールドはありません。`score` はライフサイクルイベントでは `null`、動きでは `{ value, unit: 'dB', basis }` です。`basis` は基準との差 `above_baseline` か、受信トーンの減衰 `pilot_attenuation` です。スコアは確率・信頼度・距離ではありません。

動きは毎フレーム送信しません。検知エピソードの重複を抑え、動きイベント間に 3 秒のクールダウンを設けます。クールダウンはセッションを開始し直しても継続し、抑制されたエピソードは後でまとめて送られません。開始・停止は動きとは別のライフサイクルイベントです。受信側でもイベント ID によって重複を識別します。この試作は永続キューや配送保証を提供しません。

ローカル受信サーバーは JSON のイベント形式、最大 8 KiB、発生時刻（過去 5 分〜未来 30 秒）、同じ Origin・リテラル Host・接続元のループバックを検査します。新規受信は最大 60 件/分です。重複 ID は最大 512 件、受信時刻と発生時刻の遅い方から 5 分間（境界の 1 ミリ秒を含む）保持し、同じ ID で本文を変えた再送は拒否します。履歴全体を保存せず、最新の受信 envelope と重複判定用 ID・内容ハッシュをメモリーに保持します。`GET /bridge/status` で模擬受信状態を確認できます。通常起動では受信関連ルートは `404` です。

## データと検知の制限

マイクのサンプルと FFT の処理はブラウザー内で行い、生音声、録音、会話本文、FFT 配列をブリッジのイベントに含めません。イベントは状態・日時・一時的な識別子・スコアに限定します。これらのメタデータも人の行動時間の手掛かりになるため、公開共有する前に内容を確認してください。画面や模擬受信の履歴はメモリー上のデモ用で、永続保存・音声ログ・分析サービスへの送信は実装していません。

検知がないことは不在を意味しません。静止した人の在席、人物や物の分類、距離、検知範囲、成功率は保証できません。ミュート、音量変更、機器の周波数応答、背景音などでも誤検知や見逃しが起こります。高周波音が聞こえる・不快な場合は停止してください。この試作は警備・見守り・緊急通知に用いるための信頼性を検証していません。

クラウドでの試験対象は合成データ、イベントの制限、明示的な有効化、停止、ローカル受信、純粋なアダプター変換、および仮想デバイスを用いたブラウザーのマイク経路です。実マイクや実スピーカー、実環境の精度は試験していません。テストの具体的な実行結果は[検証記録](validation.md)を参照してください。

## dot / MCP Events の接続境界

`bridge/mcp-events.js` はネットワーク I/O を行わない純粋な変換です。`toMcpEvent(event)` は共通イベントを検証し、独立したデータコピーを持つ `{ eventId, name, timestamp, data, cursor: null }` を返します。`eventDefinition` は `events/list` 用の候補定義です。`sonic.motion` はこのプロジェクトが定義したイベント名で、dot 組み込み API や作成済み接続名ではありません。

[公式 MCP Events ドキュメント](https://developers.openai.com/plugins/build/mcp-events)には dots 対応が記載されています。ただし実接続には、認証された MCP サーバー、`events/list`・`events/subscribe`・`events/unsubscribe`、購読の永続化とアクセス確認が必要です。ChatGPT が購読時に渡す callback と署名用秘密をサーバー側で管理し、HTTPS 宛先を接続時に検証し、署名付き challenge を確認してから配送します。ローカル・非公開 IP とリダイレクトを拒否し、Standard Webhooks 署名、期限、解除、再試行、重複を扱う必要があります。

この試作はその認証サーバーや実配送を実装していません。ブラウザーへ秘密を埋め込まず、秘密の発行、プラグイン接続、外部 callback への送信、dot の応答確認も行っていません。ローカルで envelope が生成できることは、dot 接続が動くことの証明ではありません。
