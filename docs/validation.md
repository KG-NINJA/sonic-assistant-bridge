Unit tests cover DSP, calibration, direction changes, obstruction, cancellation,
resource cleanup, strict event whitelisting, minimum 3-second motion cooldown,
repeated-event suppression, receiver Origin/Host/body/timestamp limits, ID
collisions, duplicate-expiry boundaries, and local/static build assets.
The root MIT license and unchanged Three.js MIT license are fetched and compared
in both static language builds.

The bridge browser test covers opt-in delivery, synthetic motion, Stop, disabled
sending, pending-request abort, hidden/pagehide stops with no automatic resume,
rejection without retry, reload reset, injected bridge failures, and English
static preview. No physical input or output is used.

The microphone browser test uses native Chromium `getUserMedia`, MediaStream
tracks, AudioContext, oscillators, and FFT processing. Chromium is started with
`--use-fake-device-for-media-stream`, a generated synthetic 20 kHz WAV capture,
and `--mute-audio`. The successful path verifies tone qualification, calibration,
a `mode: live` motion event, and explicit Stop. It checks three repeated
start/stop cycles, ended tracks, stopped oscillators, zero gains, and closed
contexts. No microphone/context/oscillator is created before explicit Start.

Permission/device failures, delayed permission, audio-processing settings,
visibilitychange, pagehide, track mute/ended and devicechange are injected test
cases; actual AudioContext suspension is also exercised. These injections do not
establish all OS-specific behavior. English `/sonic-assistant-bridge/` and Japanese
`/sonic-assistant-bridge/ja/` are served on loopback and each checked for native
fake-microphone start/stop, localized permission-denial text, a separate demo,
seven assets and both license links. Neither browser suite makes external
requests or produces uncaught page errors. Physical acoustics remain untested.

## Reproduction and evidence

Environment: Node.js `v24.19.0`, npm `11.9.0`, Chromium `154.0.8037.57` on Debian 13.
Project dependency versions are unchanged. Use Node.js 22+ for development.

```sh
npm ci
npm test
npm run lint
npm run typecheck
npm run check
npm run build
npm run build:pages
npm run demo:bridge
```

The optional browser checks use an existing Playwright/Chromium installation,
without adding Playwright to the application dependencies. On this cloud host:

```sh
PLAYWRIGHT_MODULE=file:///opt/codex/cua_node/lib/node_modules/playwright/index.mjs \
CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:browser
PLAYWRIGHT_MODULE=file:///opt/codex/cua_node/lib/node_modules/playwright/index.mjs \
CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:microphone
```

Portable evidence includes `browser-bridge-smoke.json`,
`browser-microphone-smoke.json`, and synthetic/fake-device UI screenshots.
Temporary WAV data is generated by the test and removed afterward. ZIP delivery
includes source, a portable runtime, static site, patch, concise reports and
SHA-256 checksums. It excludes Git metadata, node_modules trees, dependency
caches, credentials and routine logs. Only the required Three.js modules and
unchanged MIT text are bundled in `vendor/`. Native Windows execution remains
untested; the portable launcher paths and CRLF line endings are checked.

## Publication and remaining limits

The publication repository is `KG-NINJA/sonic-assistant-bridge`, initialized with
README commit `57219e0420e849d183b840489e6f56cd6e7a6663`. This implementation is
applied as a normal descendant, preserving that initial history. The owner has
configured Pages Source = GitHub Actions and required HTTPS for the standard
project domain. The original SonicForceField repository and site are untouched.

The source above was verified locally before publication. Public delivery must
also be established from the new commit's CI/deployment results and live assets;
see [publication verification](publication.md). Local tests do not establish
public HTTPS health, physical reception, motion accuracy, stationary presence,
distance, identity, sound pressure, or real dot delivery. The MCP Events adapter
remains a pure conversion with local mock receipt; it creates no live connection
or secrets. No real microphone or physical speaker was used in cloud tests.
